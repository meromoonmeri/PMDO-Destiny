# Écran noir au café : résultats de l’enquête locale

Base : v0.5.7, commit `ee39156a24f350b67e81740478be8505f4ff1a05`. Sauvegarde CRC valide `sauvegarde-avant-cafe-057.zip` : 21 fichiers d’origine vérifiés par blob Git. Guide de cinématiques et API du moteur de ce commit relus.

## Constats vérifiés

- La porte de la place appelle bien la carte n°2 de `town02_waterfallvillage` ; la zone indique `caféspindaaccueil` à cet index. Le marqueur n°0 existe à (290,354).
- Les trois cartes du café contiennent dix banques de terrain distinctes ; toutes les références de tuiles vérifiées existent dans les banques publiées, et la musique référencée figure dans l’arbre du dépôt. Cela ne prouve pas que l’installation de l’utilisateur charge ces fichiers correctement.
- Avant le fondu, le moteur charge et initialise la carte et son script. Une erreur dans le chargement ou dans la caméra appelée au début de `Enter` peut empêcher le fondu. En revanche, les erreurs du callback Lua `Init` sont interceptées par `ScriptEvent` et arrêtent ce callback ; cela ne prouve pas qu’elles empêchent `Enter`. La version 0.5.7 protégeait déjà le suivi, mais pas les opérations d’initialisation ni la caméra appelée avant le fondu.
- **Piste prioritaire pour l’entrée sous Windows :** `RunGroundMapScript` charge le module `destiny.ground.caféspindaaccueil` par `require`. Le moteur règle les chemins `package.path` en CP1252 sur Windows, puis rétablit UTF-8 ; le nom du module accentué transmis par Lua est en UTF-8. Le Lua embarqué utilise `fopen` pour chercher les modules (`loadlib.c`), dont le traitement dépend de la page de codes Windows. Un échec du chargement du script d’accueil peut laisser `Enter` et son fondu absents après le fondu noir. Les tests CI `executer_lua.py` remplacent explicitement `loadfile` par une lecture Python Unicode : leur succès ne teste pas ce chemin de chargement moteur. C’est une cause très plausible, non reproduite sur le Windows de l’utilisateur.
- **Défaut distinct confirmé :** `LuaEngine.CleanMapScript` insérait l’identifiant de carte directement dans une expression comme `package.loaded.caféspindaaccueil = nil`. Le parseur Lua testé refuse cette syntaxe à cause de l’accent. Le même problème touche les deux étages. Le nettoyage a lieu lors de la destruction de la carte. Le moteur intercepte et journalise l’erreur de syntaxe : le bloc ne s’exécute pas, donc le nettoyage prévu et l’appel éventuel à `Cleanup` sont omis. Cela peut laisser des modules en cache, mais ne prouve pas un blocage de transition ni l’écran noir lors de l’entrée depuis la place.

## Corrections préparées, non publiées

- `travail/engine/RogueEssence/RogueEssence/Lua/LuaEngine.cs` : sur Windows, pour une Ground à nom non ASCII, lire le script connu avec l’API Unicode .NET, le compiler depuis son texte et le fournir temporairement à `package.preload`, puis appeler `require` normalement. Les noms de cartes et de modules restent inchangés ; un chargeur préexistant est respecté. Les autres scripts conservent leur chemin de chargement. Pour le nettoyage, passer le nom comme chaîne et utiliser une clé de table, sans le concaténer comme du code Lua ; vider aussi les entrées de module qualifiées correspondant à cette Ground, sans toucher aux autres modules. L’appel facultatif `Cleanup` reste conservé.
- `travail/game/Data/Script/destiny/ground/caféspindaaccueil/init.lua` : protéger séparément les opérations d’initialisation et journaliser leurs erreurs ; après chargement ou arrivée, faire le fondu avant le recentrage facultatif, lui-même protégé. Le scénario, les personnages, la carte et les coordonnées sont conservés. Une erreur de création de porte reste possible et serait signalée : le fondu visible ne garantit pas une sortie fonctionnelle dans ce cas.

## Contrôles

- Recherche de module simulée indisponible : les trois scripts réels se chargent depuis un `preload` compilé en mémoire ; cache et rechargement fonctionnent dans le test Lua. L’ancien fragment de nettoyage échoue sur le nom accentué ; le fragment corrigé passe pour les trois cartes accentuées, un nom ASCII et un nom contenant des caractères de code, tout en préservant les autres modules. Tests Lua isolés, pas compilation C# ni exécution du chargeur KeraLua sous Windows.
- Les scénarios café préexistants passent sur doublures : première visite et suivi, retour étage, acteur absent, trajet occupé, rénovation et sieste. Cas supplémentaires : panne de caméra, panne de porte à l’initialisation et chargement, fondu exécuté et erreur journalisée.
- Aucun test réel dans le moteur Windows, aucune compilation de l’exécutable, aucune sauvegarde de joueur chargée. L’origine précise de l’écran noir à l’entrée reste à confirmer et le correctif ne peut pas être déclaré validé en jeu. Aucune publication, CI ou release n’a été effectuée.
